# 设置面板二次确认优化方案

## Context

设置面板中有 9 处"恢复默认"/"重置"/"执行"类操作在点击后直接执行，没有二次确认弹窗。用户误触会丢失自定义配置（如优先级权重、AI 提示词）或触发不可撤销的立即操作（如重建缓存、修复父子关系）。需要为这些操作添加确认弹窗，与已有的 `handleResetAll` 和 `purgeField` 保持一致。

## 确认模式

复用 SiYuan 内置 `confirm(title, text, confirmCallback)` —— 项目已在 8 处使用此模式，无需新建组件。

```typescript
import { confirm } from "siyuan";
confirm(title, text, () => { /* 执行操作 */ });
```

## 需要添加确认的 9 处操作

### 类别 A：分区重置（6 处，仅修改草稿状态，可通过取消设置放弃）

| #    | 函数                      | 文件                 | 行号 | 重置内容                            |
| ---- | ------------------------- | -------------------- | ---- | ----------------------------------- |
| 1    | `handleResetPriority`     | SettingsPanel.svelte | 347  | 优先级引擎全部权重和参数            |
| 2    | `handleResetDefaults`     | SettingsPanel.svelte | 360  | 默认重要性、工作量、语义日期解析    |
| 3    | `handleResetMyDay`        | SettingsPanel.svelte | 366  | My Day 重置时间、默认视图、默认时长 |
| 4    | `handleResetReminder`     | SettingsPanel.svelte | 372  | 提醒开关、偏移量、提示音            |
| 5    | `handleResetTaskCreation` | SettingsPanel.svelte | 385  | 任务创建目标、收件箱、笔记本        |
| 6    | `handleResetMcp`          | SettingsPanel.svelte | 380  | MCP 开关、写权限                    |

### 类别 B：AI 提示词重置（1 处，仅修改草稿状态）

| #    | 函数          | 文件                  | 行号 | 重置内容                   |
| ---- | ------------- | --------------------- | ---- | -------------------------- |
| 7    | `resetPrompt` | AiSettingsPage.svelte | 62   | 单个 AI 功能的自定义提示词 |

### 类别 C：维护操作（2 处，立即执行，不可撤销）

| #    | 函数                   | 文件                 | 行号 | 执行内容                     |
| ---- | ---------------------- | -------------------- | ---- | ---------------------------- |
| 8    | `handleRebuildCache`   | SettingsPanel.svelte | 313  | 从数据库重新加载所有任务数据 |
| 9    | `handleRebuildParents` | SettingsPanel.svelte | 328  | 检查并修复任务层级关系       |

## 关键设计：避免 handleResetAll 嵌套确认

`handleResetAll`（行 400）已有确认弹窗，其回调内部直接调用 `handleResetDefaults()`、`handleResetPriority()` 等。如果为这些函数添加确认，"全部重置"会弹出 7 个确认框。

**解决方案**：将 6 个分区重置函数的执行体抽取为 `doReset*` 内部函数，`handleReset*` 包装确认后调用 `doReset*`，`handleResetAll` 的确认回调改为调用 `doReset*`。

`handleResetAi`（行 392）和 `handleResetCustomFields`（行 396）仅被 `handleResetAll` 调用、无独立 UI 按钮，无需改动。

#### 1d. 为 handleRebuildParents 添加确认

**修改前**（行 328-345）：

```typescript
async function handleRebuildParents() {
    rebuildingParents = true;
    error = "";
    try {
        const result = await bridge.rebuildParents();
        const fixed = result?.fixed ?? result?.count ?? 0;
        const message = i18n?.rebuildParentsSuccess
            ? i18n.rebuildParentsSuccess.replace("{count}", String(fixed))
            : "Fixed " + fixed + " parent relationship(s)";
        notifyInfo(message);
    } catch (e: any) {
        console.error("[NextAction] rebuildParents failed:", e);
        error = formatRpcError(e, i18n);
        notifyError(i18n?.rebuildParentsFailed || "Failed to fix parent relationships");
    } finally {
        rebuildingParents = false;
    }
}
```

**修改后**：

```typescript
function handleRebuildParents() {
    confirm(
        i18n?.rebuildParents || "Repair parent relationships",
        i18n?.rebuildParentsConfirm || "This will check and fix task hierarchy relationships. The operation runs immediately and modifies data.",
        async () => {
            rebuildingParents = true;
            error = "";
            try {
                const result = await bridge.rebuildParents();

                const message = i18n?.rebuildParentsSuccess
```
