# 采用结果导向的思源原生项目模型

状态：accepted

NextAction 将 Project 定义为锚定在思源文档块上的有限结果承诺，而不是普通父任务或文件夹；其唯一身份是文档块上的 `custom-na-task = "2"` 项目标记。Action 可以位于任意思源位置，并通过现有 `custom-na-parent` 形成统一的逻辑父关系；指向 Project 时即表示项目归属，是否物理移动到项目文档由用户单独决定。首阶段禁止 Project 嵌套 Project。取消项目身份时只清理直接指向该项目的父关系，不递归改写更深层 Action。Project 复用现有任务状态，Outcome 和 DoD 作为项目控制字段，进度只统计叶子 Action，项目完成必须经过用户确认；所有叶子完成但尚未确认时属于“可完成候选”，不等同于健康度 `complete`；完成后新增或重开直接子行动会使项目重新进入 `doing`。这样既保留思源的笔记原生结构，又避免引入第二套生命周期、关系字段和任务清单系统；日历容量、自动排程和 AI 自动写入暂不属于首阶段能力。现有 MCP 显式写入工具在 preview/apply 确认协议设计完成前保持原契约，AI 提案不得绕过用户确认直接调用。
