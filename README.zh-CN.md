> [!IMPORTANT]
> **它改动了什么：** 在思源块上写入 `custom-na-*` 任务属性。内核 bundle 运行在思源内核进程中。
> **会不会上传数据？** 不会向插件作者回传任何遥测。AI 功能（可选）会把你配置在思源里的 AI 提供商当作出口，通过思源自带的 `/api/ai` 接口发送任务快照——插件本身从不直接调用第三方服务器。
> **怎么撤回：** 在「设置 → 集市 → 已下载」里禁用插件。点击块左侧的状态圆圈菜单 →「移除任务」即可去掉任务属性。块正文内容会保留。

**安装：** 设置 → 集市 → 搜索「今天干点啥」→ 安装

---

## 它解决的问题

你的思源笔记本里已经记着这些任务——项目笔记、会议待办、日常清单。但思源不会告诉你「下一步做什么」。任务散落在各个文档里，一旦数量多起来，挑哪一件先做就全凭感觉。

NextAction 把任意块转成带截止日、重要性、工作量的任务，再筛出当前能推进的事并排好序。任务仍然留在思源里，不需要再维护第二套系统。

## 先看效果

在任意块上输入一条斜杠命令：

```
/ntask
```

这个块就成了任务。左侧出现状态圆圈，任务进入**收集箱**。在桌面端或 browser-desktop 中，点击顶栏按钮打开完整 NextAction Tab；右侧 300px Dock 保留为紧凑入口。切到**下一步行动**，就能看到当前可执行的任务，并按计算出的优先级排序。

## 快速上手

1. 在任意文档里输入 `/ntask`（或 `/zrw`），把当前块转为任务。
2. 点击块左侧的状态圆圈，设置状态、优先级，或打开任务详情。
3. 桌面端/browser-desktop 从顶栏打开完整面板；browser-mobile 先打开 Dock，再进入完整面板。**下一步行动**显示当前能做的事，**收集箱**放着还没处理的内容。

先从这几步用起来就够了。重要性、回顾间隔、提醒、依赖、自定义字段，可以等任务变多以后再慢慢加。

### 面板入口

- **desktop 和 browser-desktop：** 顶栏按钮会在 Tab 中打开完整工作区；右侧 300px Dock 是用于快速收集和查看焦点清单的紧凑入口，窄宽度下也保持精简布局。
- **browser-mobile：** 先打开 Dock，再点击其中的完整面板入口。`MobileDockHost` 明确区分紧凑 Dock 与完整工作区，并提供返回操作和安全区适配。
- **原生 iOS/Android：** 当前插件 manifest 没有声明原生移动端后端，因此原生移动端支持不属于本文档承诺和本阶段验收范围。

<details>
<summary><b>采集命令</b> — 更多创建任务和项目的方式</summary>

- `/ntask` 或 `/zrw` — 把当前块转为任务（默认进入**收集箱**）。
- `/nproject` 或 `/zxm` — 把当前块转为项目。
- `/ntaskchildren` 或 `/zrwz` — 批量转换列表或文档子树。
- 右键块图标或文档标题图标 →「转任务」。

</details>

## 工作原理

NextAction 按 GTD 的节奏运转：先收集，再明确，放进合适的清单，定期回顾，最后只看当前能执行的事。任务就是带 `custom-na-*` 属性的普通思源块；插件通过思源 API 读取它们，算出优先级分数，再过滤视图。

<details>
<summary><b>NextAction 里的 GTD 流程</b></summary>

**收集** — 输入 `/ntask` 把块转为任务，新任务默认进入**收集箱**。收集箱里的东西不要求马上想清楚，先放进去，别让它在脑子里占位置。

**明确** — 逐条处理收集箱：

- 要做的 →「待开始」或「进行中」
- 暂时不做 →「将来/也许」
- 卡在别人或外部条件上 →「等待中」
- 已经没有价值 → 移除任务属性

需要更多上下文时，打开任务详情补充截止日、开始日、重要性、工作量、上下文、标签和备注。

**组织** — 六种状态对应不同清单：

| 状态 | 图标 | 适合放什么 |
|------|------|------------|
| 收集箱 | 浅蓝圆圈 + 下箭头 | 刚捕获，还没处理 |
| 待开始 | 灰色空心圆 | 已经明确，但还没动手 |
| 进行中 | 蓝色半填充圆 | 正在推进 |
| 等待中 | 橙色虚线圆 | 等人、等反馈、等条件 |
| 将来/也许 | 金色圆 + 三点 | 以后可能会做 |
| 已完成 | 绿色实心圆 + 白勾 | 已完成 |

优先级有五档：紧急（红）> 高（橙）> 中（蓝）> 低（灰）> 无。

任务可以嵌套。项目下面可以有任务，任务下面也可以继续拆子任务。只要子任务没做完，父任务就不会被当成「下一步行动」推到前面。

**回顾** — **回顾**视图会列出一份 GTD 风格的检查清单和到期需要回顾的任务。每个任务都可以设置回顾间隔，到时间后重新出现。

**执行** — **下一步行动**只保留当前可以推进的任务。已完成、等待中、未到开始日期、还有未完成子任务的任务都会被过滤掉。安排一天的节奏可以用**我的一天**：从下一步行动里挑任务，拖到时间线上排期。

</details>

<details>
<summary><b>优先级怎么算</b></summary>

NextAction 根据重要性、工作量、截止日期紧迫度和手动优先级算出一个分数。分数越高，任务在**下一步行动**里越靠前。

你不需要每次手动拖排序。通常只要把重要性、工作量、截止日填得差不多，列表就能给出一个够用的执行顺序。还没到开始日期的任务不会出现在下一步行动里，避免太早打扰。

优先级参数（截止日权重、开始日、重要性、衰减、增长、前瞻）可以在「设置 → 优先级参数」里调整。

</details>

## 视图

| 视图 | 用途 |
|------|------|
| 下一步行动 | 当前能做的任务，按计算得分排序 |
| 全部任务 | 未完成任务的树形总览，支持搜索、筛选和拖拽排序 |
| 项目视图 | 按项目分组查看子任务和完成进度 |
| 收集箱 | Inbox 状态任务，集中做明确处理 |
| 我的一天 | 今日计划，可用列表或时间线模式 |
| 将来/也许 | 暂时搁置的任务，可重新激活 |
| 等待中 | 依赖别人或外部条件的任务 |
| 回顾 | GTD 检查清单和待回顾任务 |
| 统计 | 完成率、状态分布等概览 |
| 提醒 | 待处理提醒集中查看 |

## 任务属性

| 类别 | 字段 |
|------|------|
| 基础 | 标题、状态、优先级 |
| 日期 | 截止日、开始日（可精确到分钟） |
| 优先级参数 | 重要性（1-7）、工作量（1-7） |
| 组织 | 上下文（@）、标签、父任务、项目 |
| 依赖 | 依赖任务、依赖模式（全部/任一）、顺序执行 |
| 重复 | 频率（日/周/两周/月/年）、间隔、起算方式 |
| 回顾 | 回顾间隔、下次回顾日期 |
| 提醒 | 截止前提醒、固定时间提醒 |
| 自定义 | 用户自定义字段 |
| 其他 | 备注 |

## 在编辑器里操作任务

块转成任务后，左侧会出现状态圆圈：

- **点击圆圈**：切换状态、设置优先级、加入我的一天、添加提醒、查看属性或移除任务。
- **在面板里左键点击圆圈**：打开状态菜单。
- **在面板里右键任务卡片**：快速改状态、优先级、我的一天、提醒等。
- **点击任务标题**：打开详情弹窗，编辑完整属性。
- **拖拽任务卡片**：在全部任务视图里调整顺序。

<details>
<summary><b>设置</b> — 五个部分</summary>

1. **常规**：任务默认值、我的一天、提醒。
2. **自定义属性**：扩展任务属性。
3. **内置 AI**：自定义内置 AI 提示词。
4. **MCP**：向 AI 客户端暴露任务工具。
5. **高级**：优先级引擎与维护。

</details>

## 常见问题

**会和单独的任务服务器同步吗？**
不会。任务就是带 `custom-na-*` 属性的普通思源块，所有数据都在你的思源工作空间里，没有外部账号或同步层。

**卸载后我的块会怎样？**
块正文保留，只移除任务属性。你也可以在不卸载的情况下，通过状态圆圈菜单单独移除某个块的任务属性。

**AI 功能会把我的数据发到外面吗？**
只有在你主动触发 AI 功能（提取任务、拆解、规划我的一天、回顾）时才会。插件调用的是思源自带的 `/api/ai` 接口，由思源转发到你配置的 AI 提供商。插件本身从不直接联系第三方服务器，也不向插件作者发送任何数据。

## 参与开发

```bash
pnpm install
pnpm run dev              # 监听模式：kernel + app 并行
pnpm run build            # 生产构建
pnpm run release          # 构建并部署到本地插件目录
pnpm run release:package  # 构建市场发布用 package.zip
```

架构说明见 [docs/ARCHITECTURE.zh-CN.md](./docs/ARCHITECTURE.zh-CN.md)。

<details>
<summary><b>发布新版本</b></summary>

发布由 Git tag 触发。发布前，先在 [CHANGELOG.md](./CHANGELOG.md) 的 `[Unreleased]` 区域中选择合适分类，至少填写一条以 `- ` 开头的更新内容，并提交该改动。没有内容的分类不会出现在 GitHub Release 正文中。

```bash
pnpm run release:patch
pnpm run release:minor
pnpm run release:major
pnpm run release:current
pnpm run release:version -- 1.2.3
```

命令会校验并封版更新日志，在需要时同步 `package.json` 和 `plugin.json` 的版本号，提交发布文件，创建 `vX.Y.Z` tag，并推送 commit 和 tag。第一次发布时，如果当前版本号已经正确，可以用 `release:current`。GitHub Actions 收到 tag 后会构建 `package.zip`，使用该版本的更新日志作为 GitHub Release 正文，并附上相对前一版本的完整变更链接。

</details>
